Desenvolvimento do E-commerce Poliglota com Django
Vamos desenvolver o projeto utilizando Python + Django + Supabase + MongoDB + Redis, com implantação na nuvem.

O objetivo será construir uma plataforma de e-commerce multiempresa, na qual diferentes empresas poderão ter suas próprias contas administrativas, cadastrar produtos e receber pedidos pelo WhatsApp.

Como o escopo é acadêmico, vamos priorizar os requisitos obrigatórios, mas deixando a arquitetura organizada para que você consiga demonstrar e explicar cada banco de dados na apresentação.

8. Criando a estrutura SQL no Supabase
Entre no Supabase Dashboard  e crie um projeto.

Depois, acesse:

Execute o seguinte script:


sql
-- PERFIS DOS USUÁRIOS
CREATE TABLE public.perfis (
    id UUID PRIMARY KEY REFERENCES auth.users(id)
        ON DELETE CASCADE,

    nome VARCHAR(150) NOT NULL,

    email VARCHAR(255) NOT NULL,

    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- EMPRESAS
CREATE TABLE public.empresas (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    nome VARCHAR(150) NOT NULL,

    cnpj VARCHAR(18) UNIQUE,

    email VARCHAR(255),

    telefone VARCHAR(30),

    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- USUÁRIOS VINCULADOS ÀS EMPRESAS
CREATE TABLE public.empresa_usuarios (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    empresa_id UUID NOT NULL
        REFERENCES public.empresas(id)
        ON DELETE CASCADE,

    usuario_id UUID NOT NULL
        REFERENCES public.perfis(id)
        ON DELETE CASCADE,

    papel VARCHAR(30) NOT NULL DEFAULT 'admin',

    created_at TIMESTAMPTZ DEFAULT NOW(),

    UNIQUE (empresa_id, usuario_id)
);

-- ÍNDICES
CREATE INDEX idx_empresa_usuarios_usuario
ON public.empresa_usuarios(usuario_id);

CREATE INDEX idx_empresa_usuarios_empresa
ON public.empresa_usuarios(empresa_id);
O relacionamento será:

auth.users: autenticação gerenciada pelo Supabase.

perfis: informações complementares dos usuários.

empresas: cadastro das empresas.

empresa_usuarios: associação e permissões.

Importante: habilite RLS nas tabelas e crie políticas de acesso adequadas. O backend deverá validar a identidade e a associação do usuário antes de realizar operações. Não exponha uma chave service_role no navegador.

9. Primeira funcionalidade: login administrativo
Arquivo: apps/accounts/services.py


python
from integrations.supabase_client import supabase


def autenticar_usuario(email, senha):

    try:
        resposta = supabase.auth.sign_in_with_password({
            "email": email,
            "password": senha
        })

        return {
            "sucesso": True,
            "usuario": resposta.user,
            "access_token": resposta.session.access_token,
            "refresh_token": resposta.session.refresh_token
        }

    except Exception:
        return {
            "sucesso": False,
            "erro": "E-mail ou senha inválidos."
        }
Arquivo: apps/accounts/views.py


python
from django.shortcuts import render, redirect
from django.contrib import messages

from .services import autenticar_usuario


def login(request):

    if request.method == "POST":

        email = request.POST.get("email")
        senha = request.POST.get("senha")

        resultado = autenticar_usuario(email, senha)

        if resultado["sucesso"]:

            request.session["access_token"] = (
                resultado["access_token"]
            )

            request.session["refresh_token"] = (
                resultado["refresh_token"]
            )

            request.session["usuario_id"] = str(
                resultado["usuario"].id
            )

            request.session.cycle_key()

            return redirect("admin_dashboard")

        messages.error(request, resultado["erro"])

    return render(request, "accounts/login.html")
Essa é a primeira versão do login. Antes de liberar o painel, ainda precisamos validar o token, conferir a associação do usuário à empresa, implementar renovação de sessão e proteger as rotas administrativas.

Anúncio

aonde é guardada a senha do usuário?

A senha do usuário fica armazenada no Supabase Auth, e não diretamente na tabela perfis nem no MongoDB.

O Supabase gerencia a autenticação e armazena as senhas utilizando hash criptográfico, evitando que sejam guardadas em texto puro.

Como funciona no nosso projeto?
Quando um administrador cria uma conta:

O Django envia e-mail e senha ao Supabase Auth.

O Supabase registra o usuário em auth.users.

A senha é armazenada de forma protegida (hash).

O Supabase gera um UUID para identificar o usuário.

Esse UUID é utilizado na tabela perfis do PostgreSQL.

Estrutura no banco Supabase
Local

Informação armazenada

auth.users

ID, e-mail e dados de autenticação

auth.users.encrypted_password

Hash da senha

public.perfis

Nome, e-mail e dados complementares

public.empresas

Dados das empresas

public.empresa_usuarios

Associação entre contas e empresas

Relacionamento da autenticação

Supabase Auth

E-mail + senha protegida + UUID

public.perfis

UUID + nome + e-mail

public.empresa_usuarios

Identifica a empresa e o papel do usuário

Como cadastrar um usuário pelo Django?
Podemos criar uma função:


python
from integrations.supabase_client import supabase

def cadastrar_usuario(email, senha):

    resposta = supabase.auth.sign_up({
        "email": email,
        "password": senha
    })

    return resposta.user
Depois, utilizamos o UUID retornado para criar o registro correspondente em public.perfis.

Importante: nunca salve a senha original em perfis, MongoDB ou Redis. Também não registre senhas em logs.

Dessa forma, nosso projeto terá autenticação centralizada e segura pelo Supabase, enquanto o PostgreSQL mantém os relacionamentos entre contas e empresas.
